## 📌 这是什么

上游 RikkaHub 是一个做得很完整的对话客户端。本 fork 在它之上换了一种组织方式：把「和 AI 一起做事」拆成四个板块，各有自己的列表和配置，记忆与工作区也分开，互不串味。

| 板块 | 一句话 |
|---|---|
| **工作** | 和 AI 一起干活：工具、文件、工作区、搜索 |
| **角色** | 和 AI 角色相处：角色卡、人设、长期记忆（规划中） |
| **群组** | 多个 AI 一起做事：组员、发言顺序、副群主 |
| **脉搏** | AI 自己运转：心跳、计划任务、监视器 |

原本的「聊天」之所以改叫「工作」，是因为它早就不只是闲聊：读写文件、跑命令，查网页、调工具，另外还能连 MCP 服务器、开工作区。把这些放进「聊天」这个名字里，会低估它实际在做什么。

**上游的能力一项没删。** 多供应商、MCP，以及技能和工作区这些都在，完整的清单在下文，四个板块里都能用，只是被放到了合适的位置。上游每次发版，我们跟进合并，不另起炉灶。

**不是 RikkaHub 官方版本。** 本仓库的一切都建立在上游工作之上；本 fork 的问题请提到本仓库，与上游无关。

- **版本号规则**：`{上游版本}-work.{n}`，例如 `3.2.0-work.3`；每次跟进新的上游版本时 `n` 归 1
- **语言**：仅保留 English、简体中文、繁體中文
- **分发**：构建产物通过本仓库的 GitHub Releases 发布

## 🧭 四个板块

### 01 工作：和 AI 一起干活

单对单的界面。能调工具、读写文件，也能跑命令、查网页，或者只是聊两句。

- **三档工具审批** —— 每个助手独立保存：**需要询问**（每次确认）、**部分询问**（仅高风险确认，默认）、**完全允许**（不确认）。风险按 L0~L3 分级，未登记工具默认按最高风险处理。
- **工作区** —— 基于 proot 的本地 Linux 环境，或通过 SSH 连远程机器；`/workspace` 里放文件。Markdown 可在渲染与源码间切换；HTML / SVG 本地资源限于文档目录，禁止外网加载，HTML 脚本默认关闭。SSH 暂不支持本地关联资源预览。
- **记忆** —— 逐条记忆与文件式记忆两套并存；多个助手可以共享同一个记忆分组，同时保留私有记忆与内置全局记忆。复制助手、切换记忆归属时可以逐条勾选要带走哪些，并在「复制 / 移动」之间选。
- **内置浏览器（凭据隔离）** —— 遇到需要登录、验证码或动态渲染的页面时，由 AI 请求打开浏览器，**用户亲自登录**，AI 只读取本机过滤后的内容。固定 8 个工具，不提供任意 JavaScript、原始 DOM、Cookie、无头模式、截图或 OCR；支付、删除、授权、发布、转账、密码框与文件操作**硬拒**，无法通过审批绕过。
- **搜索服务商** —— 上游自带十余家；本 fork 另接 **随想搜索**（0.06 元/次，失败不扣费）、**DeepSeek 官方搜索与抓取**（0.005 元/次，带专供模型阅读的长摘要）、**AnySearch**（可匿名，带 Key 每天 1000 次）。
- **DeepSeek 网页版（免费）** —— 用网页登录态而不是 API Key 驱动对话，默认使用只读工具白名单与请求节流；自定义能力须显式开启并确认风险。可以用「粘贴 cURL」一次导入登录凭据，不必再自己拆 Token 与 Cookie。

### 02 角色：和 AI 角色相处（规划中）

这个板块尚未实现，下面是方向。

现在的角色扮演是把角色做成助手，塞进工作列表里，跟干活的助手混在一起。这个板块把两者分开。

- **角色是独立实体**，不占用助手列表，也不复用助手那套设置；两边能用同一批工具，但配置、记忆、会话彼此独立
- **自己的会话列表**，已有的助手会话可以按你勾选迁移过来，逐个选「复制」还是「移动」
- **兼容酒馆（SillyTavern）角色卡**：导入 PNG / JSON，字段映射、示例对话、世界书、正则脚本、宏引擎
- **记忆改用文件形式**，另可只读引用工作侧的指定记忆
- 针对角色扮演里常见的「AI 味」，例如「我接住了」「我得先明说」这种在演助理、不在演角色的写法，从提示词、示例对话、深度注入、正则清洗几层一起压

### 03 群组：多个 AI 一起做事

抽屉顶部的第二个模式。几个组员围着一张桌子，按顺序发言。

- **独立组员库**：名称、头像、模型、提示词、流式输出、标签、数值参数（温度 / Top P / 上下文条数 / 最大 Token），支持长按拖拽排序
- **群组配置**：组员增删与优先级、MCP、本地工具、扩展（提示词注入 / 世界书 / 技能）、群组记忆、自定义请求头与请求体、背景、压缩设置、群级思考等级
- **群聊生成**：按顺序串行发言，每个组员能看到前面的发言；支持多会话、完整群复制、副群主分派、@ 点名、消息双向引用
- **群内昵称与头像**：按群隔离，历史气泡实时解析，不重写历史
- **群聊压缩**：手动压缩、分层摘要和可编辑提示词保留；自动压缩统一使用全局开关与阈值。

### 04 脉搏：AI 自己运转

抽屉顶部的第三个模式。与前两个不同，它不等你开口，按时间自己运转，有事才来找你。

- **心跳** —— 按固定间隔（默认 30 分钟）自检：看记忆、看待办、看监视器有没有变化。没新情况就安静，不打扰你
- **计划任务** —— 到点执行一件事，支持一次性、循环（五字段 cron）、随心跳三种。任务由 AI 创建，你只需要说「每天早上 9 点提醒我交作业」
- **监视器** —— 本地定时轮询（电池 / 网址 / 命令），**只有变化时才叫模型**，不会反复播报「一切正常」
- **感知** —— 可选读取通知与短信。首次启用跳过已有内容；正文不回传给模型，只给条数与发件人；命中验证码规则时先整条屏蔽再截断
- **自己的记忆** —— 独立的记忆桶，与其他板块不共享；顶栏可进记忆页，分「记忆 / 做梦」两页签，把零散记录整理成文件
- **自己的工具与工作区** —— 信息、记忆、日程、闹钟、文件读写、命令执行、短信，逐项开关，危险项默认关；首次进入自动铺工作区模板
- **保活与成本** —— 常驻通知 + 精确闹钟 + WorkManager 双段调度 + 电池优化 / 自启动引导 + 回前台自愈；抽屉显示今日 token 与估算费用

四个板块之间，记忆是**只读可见**的关系：谁都不能写别人的记忆桶。

## 🔧 贯穿全平台的改动

这些不属于某一个板块，四个板块都在用。

- **记忆体系** —— 分组、逐条迁移、聊天与群聊双向导入；默认复制，移动共享记忆前会提示影响范围
- **工具审批** —— L0 只读 / L1 自管理 / L2 新增 / L3 改写，四档；模式层只能升级、不能降级，避免削弱工具自身的安全声明
- **视频与工作区上传** —— Google 保留原生视频输入；其他供应商的历史视频仅在请求副本中转为文字占位，原消息保留。视频、压缩包等非聊天附件可上传到绑定工作区，单文件上限 2 GiB；未绑定时保留草稿并提示选择工作区
- **日历删除** —— 新增 `calendar_delete`，删除始终需要确认
- **思考模式推理回传修复** —— DeepSeek 思考模式在工具调用后继续生成时，自动完整回传历史 `reasoning_content`，修复 HTTP 400 中断
- **按供应商的加载动画** —— 每个供应商可独立选择：按品牌自动匹配、内置预设、自定义 GIF / 图片。内置 OpenAI 旋转、Claude 星芒、Gemini sparkle、DeepSeek 脉冲与通用呼吸
- **液态玻璃** —— Android 13+ 在输入栏使用真实折射与色散；低版本或渲染异常自动回退到模糊玻璃，不会崩溃
- **fork 自有更新检查** —— 只读取本仓库的 GitHub Releases；发现新版本跳转发布页，由你自行下载
- **稳定性** —— 生成期间持有并续租 `PARTIAL_WAKE_LOCK`，不设应用层生成时限，也不因休眠主动取消；请求日志使用活动耗时并单列休眠时长；修复「上次退出在群组模式、重启回到聊天模式」的启动竞态
- **界面与品牌** —— 应用名统一为 `RikkaHub Work`，关于页只保留本仓库链接，移除赞助与导出水印

## 📥 安装与升级

到本仓库的 **Releases** 页面下载 APK。

- **包名**：`me.rerere.rikkahub.plus` —— 与上游的 `me.rerere.rikkahub` 不同，所以**本 fork 可以和官方 RikkaHub 共存**
- **升级本 fork**：直接覆盖安装。签名必须一致、versionCode 不能倒退，否则系统拒绝安装
- **从其它 fork 或官方版转过来**：需要先卸载，签名不同装不上
- 提供三种构建：`arm64-v8a`、`x86_64` 和 `universal`，多数手机选 `arm64-v8a`；实际包体积以对应 Release 附件为准

> [!WARNING]
> **数据库只升不降。** 当前发布版数据库为 **33**；本地 `3.3.0-work.1` 已升级到 **34**。无法直接覆盖降级至 DB33 或更早版本；回退前必须处理数据与备份。
> **升级前请先在「设置 → 备份」做一次完整备份（勾选包含数据库）**，并保留一份当前版本的 APK。设置、对话和 API Key 都在应用私有目录里，卸载即丢失。

- [Coil](https://coil-kt.github.io/coil/)（图片加载）
- [Material You](https://m3.material.io/)（UI 设计）
- [Navigation 3](https://developer.android.com/guide/navigation/navigation-3)（导航）
